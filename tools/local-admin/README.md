# Локальная панель демо

Из корня репозитория: `node tools/local-admin/server.mjs --open`, либо двойной щелчок по `start-admin.cmd`. Требуются Node 22 и Docker Desktop. Откройте **http://127.0.0.1:13200**; оставьте окно терминала работающим. `Ctrl+C` закрывает панель, но сохраняет работающие проекты и туннели. Не запускайте несколько окон панели одновременно.

- **Запустить:** поднять подготовленные образы, дождаться готовности frontend и зависимостей, открыть Cloudflare Quick Tunnel. Уже работающий туннель сохраняет ссылку.
- **Скрыть ссылку:** остановить только туннель; локальный сайт остаётся доступен.
- **Остановить:** после подтверждения закрыть туннель и остановить контейнеры этого Compose-проекта. Тома и данные не удаляются.

Это управление существующими демо, без пересборки, seed и обновления кода по нажатию. Для первоначальной подготовки Flowing Short используйте `node scripts/demo.mjs start`; другие проекты сначала подготовьте по их README. После нового запуска туннеля адрес может измениться. Статус контейнеров и наличие ссылки не гарантируют доступность Cloudflare из интернета — перед встречей откройте ссылку сами.

Панель слушает только `127.0.0.1`, проверяет Host, Origin и CSRF. Не направляйте Cloudflare на порт панели и не публикуйте её через reverse proxy. Это инструмент доверенного локального пользователя, имеющего доступ к Docker; он не предназначен для нескольких пользователей или удалённого администрирования. Секреты из `.env`, Docker inspect и полные логи команд не отдаются браузеру.

## Проекты

При первом запуске создаётся игнорируемый файл `.runtime/local-admin/projects.json`. В него добавляется Flowing Short; соседний Flowing Delivery обнаруживается, если его существующий Windows quick tunnel и метаданные совпадают. Настройки пользователя при следующих запусках не перезаписываются.

Чтобы подключить ещё один подготовленный Compose-проект, закройте панель, добавьте запись в массив JSON и запустите панель снова:

```json
{
  "id": "another-demo",
  "name": "Другой проект",
  "cwd": "C:\\Projects\\another-demo",
  "composeProject": "another-client-demo",
  "files": ["compose.yaml", "compose.demo.yaml"],
  "envFile": ".runtime/demo.env",
  "profiles": ["share"],
  "localUrl": "http://127.0.0.1:13100",
  "frontend": "frontend",
  "tunnel": {"kind": "compose", "service": "tunnel"}
}
```

`composeProject` должен точно совпадать с существующим именем Compose-проекта; `frontend` и `tunnel.service` — с сервисами. Порты должны быть различными, привязаны к loopback, а данные — находиться в постоянных томах. `envFile` — путь, а не содержимое секретов. При необходимости `environment` задаёт несекретные overrides, например `{"DEMO_PORT":"5180"}`. Этот файл — доверенная локальная конфигурация, не загружайте чужие registry/Compose-файлы.

Для существующего Windows cloudflared используется `tunnel: {"kind":"native", "executable":"C:\\Tools\\cloudflared.exe"}`. Процесс определяется по executable и точному локальному адресу; перед остановкой повторно проверяются PID и время старта. Несколько совпадающих процессов требуют ручного разбора. Новые PID/логи хранятся в `.runtime/local-admin/`; после перезапуска панель находит оставленный ею туннель. Named Tunnels и управление аккаунтом Cloudflare не поддерживаются.

Новый проект не должен направлять туннель на админку. Не запускайте параллельно другие скрипты управления тем же проектом. Если команда прервалась, проверьте статус: часть действий могла успеть выполниться. При недоступном Docker панель показывает неизвестный статус, а не утверждает, что проект остановлен.

## Проверки

```sh
node --test tools/local-admin/admin.test.mjs
npm ci --prefix frontend
npx --prefix frontend playwright install chromium
node --test tools/local-admin/browser.test.mjs
```

Эти проверки включены в GitHub Actions. Браузерные тесты используют настоящий HTTP/CSRF и изолированную замену исполнителя команд; реальные проекты не затрагиваются. При ошибках screenshots и traces сохраняются в `frontend/test-results/`.

Для отдельной реальной проверки Docker/Cloudflare: в PowerShell `$env:ALLOW_SYNTHETIC_TESTS='true'; node tools/local-admin/smoke.mjs`. Она публикует только синтетический ответ, создаёт отдельные проекты `flowing-admin-test-*`, проверяет start/hide/stop, сохранность тестовых данных и удаляет только собственные временные контейнеры/тома. Проверка Windows-процесса выполняется, если найден установленный работающий cloudflared. Рабочие демо не останавливаются.
